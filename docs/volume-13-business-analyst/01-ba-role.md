# 13.1 — The Role of the Insurance BA

## 13.1.1 What Is an Insurance Business Analyst?

An **insurance business analyst (BA)** bridges the gap between business stakeholders (underwriters, claims staff, product managers, executives) and technology teams (developers, configurators, testers, vendors). BAs in insurance translate business needs into requirements, processes, and system change.

### Core Responsibilities

| Responsibility | Description |
|---------------|-------------|
| **Requirements gathering** | Elicit business needs from stakeholders |
| **Requirements documentation** | Write BRDs, user stories, functional specs |
| **Process analysis** | Document and redesign business processes |
| **Gap analysis** | Identify differences between current and target states |
| **Data analysis** | Analyze data to support decisions and validation |
| **Testing support** | Support SIT/UAT, defect triage |
| **Change management** | Support training and adoption |
| **Vendor coordination** | Work with software vendors and implementation partners |
| **Subject matter expertise** | Understand insurance domain deeply |

---

## 13.1.2 Where BAs Work

| Area | What BAs Support |
|------|-----------------|
| **Underwriting** | Product configuration, referral rules, workflow changes |
| **Claims** | Claims system projects, FNOL changes, payment workflows |
| **Actuarial** | Rate filings, rating logic validation, data extracts |
| **Product** | New products, endorsement changes, coverage updates |
| **Operations** | Process improvement, automation, quality |
| **Finance** | Billing changes, reporting requirements |
| **Compliance** | Regulatory reporting, audit support |
| **Technology** | Core system implementations (Guidewire, Duck Creek, Majesco) |

---

## 13.1.3 BA vs. Related Roles

| Role | Focus | Compared to BA |
|------|-------|---------------|
| **Business analyst** | Requirements, process, business change | — |
| **Product owner** | Product backlog, prioritization | Agile product ownership |
| **Underwriter** | Risk assessment and decisions | Uses BA outputs |
| **Solution architect** | Technical design and architecture | Implements BA requirements |
| **Project manager** | Schedule, budget, risk | Manages BA's work |
| **Data analyst** | Statistical analysis and reporting | Analyzes data BA documents |
| **QA tester** | Test execution, defects | Validates BA's requirements |

## 13.1.4 Key Skills

| Skill | Description |
|-------|-------------|

| **Process modeling** | Flowcharts, swimlanes, BPMN |

## 13.1.5 BA Deliverables

### Documentation

| Deliverable | Purpose |
|-------------|---------|
| **Business Requirements Document (BRD)** | Captures business needs and scope |
| **Functional Requirements Document (FRD)** | Describes system behavior |
| **User stories** | Agile requirements with acceptance criteria |
| **Process maps** | Current/future state workflows |
| **Use cases** | Actor–system interactions |
| **Data dictionary** | Field definitions and source |
| **Traceability matrix** | Requirements to tests mapping |
| **Test scenarios** | Business test cases |
| **Training material** | User guides, quick reference |

### Analysis Products

| Product | Purpose |
|---------|---------|
| **Gap analysis** | Current vs. target comparison |
| **Impact assessment** | Effect of change on processes/systems |
| **Options analysis** | Solution alternatives with recommendations |
| **Functional specs** | Detailed behavior for developers |

## 13.1.6 The BA in Project Lifecycles

### Waterfall

```
Initiation → Requirements → Design → Build → Test → Deploy → Support
```

| Phase | BA Activity |
|-------|-------------|
| **Initiation** | Feasibility, scope definition |
| **Requirements** | Elicit and document BRD/FRD |
| **Design** | Validate logic, support functional design |
| **Build** | Clarify requirements, answer questions |
| **Test** | Support UAT, triage defects |
| **Deploy** | Training, go-live support |
| **Support** | Hypercare, requirements for fixes |

### Agile

```
Backlog → Sprint Planning → Development → Sprint Review → Retrospective
```

| Ceremony | BA Activity |
|----------|-------------|
| **Backlog refinement** | Write user stories, acceptance criteria |
| **Sprint planning** | Prioritize, estimate |
| **Development** | Clarify, answer questions quickly |
| **Sprint review** | Demonstrate, gather feedback |
| **Retrospective** | Improve process |

---

## Key Takeaways

1. **The BA bridges business and technology** — translating needs into requirements.
2. **BAs work across underwriting, claims, product, and operations**.
3. **Core skills** are elicitation, documentation, process analysis, and communication.
4. **Insurance domain knowledge** is essential — not just generic BA skills.
5. **Deliverables** include BRDs, user stories, process maps, and test scenarios.
6. **BAs adapt to both waterfall and agile** delivery models.
